# Ручная настройка физики

Все параметры движения, вращения, размеров и хитбоксов, камеры и задержек попытки
находятся в [`src/constants.rs`](../src/constants.rs). Оформление интерфейса,
цвета и размеры PNG остаются в модулях отображения. Размер спрайта и физический
хитбокс могут различаться: например, корпус корабля рисуется внутри и за пределами
его физического квадрата.

Единицы: расстояние — игровые единицы, скорость — единицы/с, ускорение — единицы/с²,
углы — градусы, время — секунды. Один блок по умолчанию равен 80 единицам.

| Группа | Что менять |
| --- | --- |
| Куб | `JUMP`, `GRAVITY`, `CUBE_ROTATION_SPEED`, `CUBE_ROTATION_LERP_SPEED`, `ROTATION_ALIGNMENT_STEP` |
| Корабль | `SHIP_GRAVITY`, `SHIP_THRUST`, `SHIP_MAX_RISE_SPEED`, `SHIP_MAX_FALL_SPEED`, `SHIP_ROTATION_FACTOR`, `SHIP_ROTATION_LERP`, `SHIP_MAX_ANGLE` |
| Волна | `WAVE_SPEED`, `WAVE_ANGLE`, `WAVE_WIDTH`, `WAVE_HEIGHT` |
| Орбы и пады | `ORB_JUMP_FORCE`, `JUMP_PAD_CUBE_FORCE`, `JUMP_PAD_SHIP_FORCE` |
| Новые режимы | `ROBOT_*`, `BALL_*`, `SPIDER_*`; робот имеет отдельную скорость вращения |
| Контакты | `*_HITBOX_*`, `*_GROUND_HITBOX_SCALE`, `SURFACE_CONTACT_TOLERANCE` |
| Камера и земля | `POSITION_ON_SCENE_COEF`, `CAMERA_FOLLOW_SPEED`, `MAX_SHIFT_Y`, `PLAYER_TO_GROUND_PROXIMITY_THRESHOLD`, `GROUND_*` |
| Попытки | `RESPAWN_DELAY`, `SPAWN_REVEAL_TIME`, `RESTART_FADE_TIME`, `DEATH_FADE_TIME` |

`CUBE_ROTATION_SPEED = 470` означает 470° в секунду, или около 1,958° за тик при
240 Гц. В Rust применяется `rotation -= speed * DT`: знак отражает ось Y вверх.
В C++ ось Y направлена вниз, поэтому там используется сложение. Не нужно менять
знак константы для сохранения того же визуального направления.

`CUBE_ROTATION_LERP_SPEED` управляет выравниванием куба на земле, а не вращением
в полёте. В меню скорость вращения берётся из той же константы, но прыжки и
выравнивание там вычисляются аналитически.

При текущих `JUMP = 1850`, `GRAVITY = 9450`, `SPEED = 900` контрольный прыжок
занимает 93 тика, проходит 348,75 единицы и достигает высоты 177,231771 единицы.
Эти значения сохранены после ручной правки пользователя. Сами формулы приближённо:

```text
высота ≈ JUMP² / (2 × GRAVITY)
время полёта ≈ 2 × JUMP / GRAVITY
дальность ≈ SPEED × время полёта
```

На практике результат отличается от непрерывных формул из-за дискретного шага
и разрешения контактов. Изменение `GRAVITY` влияет также на полёт куба после
орба или пада, а их начальный импульс задаётся отдельно.

## Сопоставление с C++

| C++ `headers/constants.h` | Rust `src/constants.rs` | Примечание |
| --- | --- | --- |
| `CUBE_GRAVITY` | `GRAVITY` | То же ускорение |
| `CUBE_JUMP_STRENGTH` | `JUMP` | То же значение импульса |
| `CUBE_ROTATION_SPEED` | `CUBE_ROTATION_SPEED` | Градусы/с |
| `CUBE_ROTATION_LERP_SPEED` | `CUBE_ROTATION_LERP_SPEED` | Коэффициент выравнивания на земле |
| `GAME_SPEED` | `SPEED` | Общая горизонтальная скорость |
| `SHIP_JUMP_STRENGTH` | `SHIP_THRUST` | Ускорение при удержании |
| `SHIP_ROTATION_LERP_SPEED` | `SHIP_ROTATION_LERP` | Коэффициент поворота |
| `WAVE_SPEED`, `WAVE_ANGLE` | Те же имена | Модуль вертикальной скорости: `WAVE_SPEED / √2` |
| `ORB_JUMP_FORCE`, `JUMP_PAD_*_FORCE` | Те же имена | Независимы от `JUMP` |
| `GROUND_AND_CEILING_RESIZE_DURATION` | `GROUND_TRANSITION_TIME` | **400 миллисекунд → 0,4 секунды** |
| `RESPAWN_TIME_AUTO` | `RESPAWN_DELAY` | **500 миллисекунд → 0,5 секунды**; сейчас оставлена задержка 1 с по предыдущему запросу |
| `CEILING_HEIGHT` | Не равен `CEILING` | В Rust `CEILING = 1414` — абсолютный Y верхней границы, а не отступ 20 от верха |

`SHIP_DISPLACEMENT_MULTIPLIER = 2` сохраняет два перемещения Y внутри старого
`Ship::update`. Значение 1 даёт одно перемещение за тик; при этом меняется весь
профиль корабля, даже если его ускорения и лимиты скорости остаются прежними.
Это параметр совместимости Rust, отдельной константы для него в C++ не было.

## Почему одинаковые числа не дают полного совпадения

* В C++ `GameEngine::tick` после пачки фиксированных шагов дополнительно вызывает
  `handleOrbJump()` и `player->jump()`. В Rust нажатия расходуются внутри тиков
  и не зависят от количества отрисованных кадров.
* В C++ `checkCollisions` и `checkPortalCollisions` выполняются перед вертикальным
  `player->update`. В Rust сначала выполняется движение, затем разрешаются контакты.
* C++ куб проверяет приземление перед вращением, нормализует угол и применяет
  порог доводки 0,1°. В Rust выбор вращения/выравнивания происходит до разрешения
  вертикальных контактов; нормализация и этот порог не реализованы. Константа
  выравнивания не меняет порядок операций.
* У C++ волна плавно приближается к целевому углу с коэффициентом 10. В Rust угол
  волны меняется сразу; отдельной константы сглаживания нет, поскольку такого
  алгоритма пока нет.
* Камера C++ зависит от размера сцены и использует условия подъёма/спуска и
  линейное сглаживание. В Rust высота мира фиксирована, а вертикальная камера
  использует экспоненциальное сглаживание и ограниченный целевой сдвиг.
* Контакт корабля с полом в C++ содержит повторную запись ранее вычисленного
  `targetY`. В Rust поверхности ограничивают итоговую позицию после перемещения.

Эти отличия требуют изменения алгоритмов, а не подбора констант. Перенос
параметров в общий файл их намеренно не меняет; исправления орбов и плавного
возрождения сохраняются.

## Быстро измерить результат

После изменения констант запускайте измерение без окна, графики и звука:

```sh
cargo run --no-default-features --example physics_probe
```

Программа из [`examples/physics_probe.rs`](../examples/physics_probe.rs) печатает
реальную длительность, дальность и высоту прыжка, угол при приземлении и после
выравнивания, а также положение, скорость и угол корабля при удержании и отпускании.
Для проверки ощущений затем запускайте `cargo run --release`.

Тест `cube_jump_matches_the_current_cpp_profile_parameters` фиксирует конкретный
профиль 1850/9450. Если вы намеренно меняете траекторию, обновляйте его контрольные
значения по ожидаемому результату. `HZ` обычно менять не нужно. При существенном
увеличении размеров объектов учитывайте запасы поиска `COLLISION_SEARCH_*`.
